# KFL — сезоны, групповой турнир и плей-офф

Дата завершения проверки: 15 октября 2026, Asia/Bishkek.

## Утверждённый регламент

По последнему уточнению пользователя из каждой группы выходят **места 1–4**, места 5–6 выбывают. Предварительного раунда нет.

- 24 спортсмена, четыре группы A–D по шесть.
- Пять туров по три схватки на группу: 15 в группе, **60 в категории**.
- 16 участников в 1/8 финала → 1/4 → 1/2 → финал: **15 схваток плей-офф**.
- Бронзовая схватка не добавлялась: её нет в согласованном регламенте.

## Что реализовано

### Сезоны и независимые турниры

`/admin/seasons` и `/seasons`: создание/редактирование, даты, статус, описание, итоги и связанные турниры. Редактор турнира позволяет выбрать сезон или снять связь. Спортсмены остаются глобальными, схватки принадлежат турнирам, формула глобального рейтинга сохранена.

Статусы современных циклов находятся в добавочной SeasonCycle. Старое поле Season.isActive сохранено для архивной совместимости. Оно не переключает глобальный рейтинг на сезонный. Старые сезоны и спортивные данные не удалялись.

### Группы и расписание

В карточке турнира добавлен «Групповой турнир» с выбором категории и шаблоном KFL Naryn Open. Распределение задаётся вручную или явно выбранным алфавитным порядком. Скрытой случайной жеребьёвки нет.

Предпросмотр показывает все пары без записи в БД. Подтверждение создаёт 60 Match и связи TournamentBout в одной транзакции. Настраиваются время начала и интервал. Метод вращения обеспечивает ровно одну встречу каждой пары и не более одной схватки спортсмена в туре. Повторная и конкурентная генерация защищены блокировкой турнира и уникальными индексами.

Повторно проверяются регистрация, активность спортсмена, категория, дивизион и возраст по году турнира. Профили блокируются на время проверки/генерации. В сформированную категорию нельзя добавлять произвольные пары через старый редактор или незаметно менять состав.

Процедура «Перераспределить группы» требует причины и отсутствия начатых схваток/сохранённых результатов. Прежние пары остаются как отменённые. Для сыгранного турнира сначала требуются явные отмены результатов в обратном порядке; автоматического стирания результатов нет.

### Очки, места и утверждение

- DECISION: 3 победителю, 1 проигравшему.
- PIN / TECHNICAL_FALL / FORFEIT: 4 победителю, 1 проигравшему.
- Каждая победа считается ровно один раз; досрочные победы — отдельная колонка.
- Групповые очки вычисляются из актуальных результатов и не записываются в глобальный Ranking.
- Глобальный рейтинг продолжает учитывать завершённые схватки по существующей формуле.

Таблица содержит место, спортсмена, клуб, проведённые схватки, победы, поражения, досрочные победы и групповые очки. Приоритеты: очки → победы → личная встреча только для блока из двух равных спортсменов → досрочные победы. Для трёх и более попарный head-to-head не применяется. Неустранённое равенство не получает произвольного места.

Администратор утверждает порядок с обязательной причиной. API позволяет переставлять только неразрешённые равные места, проверяет полный уникальный порядок и сохраняет решение в AuditLog. Подтверждение связано с хешем результатов; устаревшую таблицу подтвердить нельзя.

### Плей-офф, продвижение и исправления

Фиксированный прозрачный посев 1/8: **A1–B4, C2–D3, B1–A4, D2–C3, C1–D4, A2–B3, D1–C4, B2–A3**. Победители соседних пар встречаются дальше. Одна группа разведена по четвертям: её участники не встретятся раньше полуфинала. После утверждения таблиц администратор отдельно подтверждает показанный посев.

Сразу создаются 15 слотов; Match следующего раунда появляется, когда известны оба победителя. Результат сохраняется существующим сервисом вместе с рейтингом, чемпионством и продвижением в одной транзакции.

Идентичный повтор не меняет групповые очки и не пересоздаёт сетку. Исправление/отмена требуют причины. Если зависимая схватка началась или завершена, раннее исправление отклоняется целиком. Сначала отменяются поздние результаты в обратном порядке. Неначатые устаревшие пары остаются как CANCELLED, а не стираются из Match.

Изменение значимого группового результата снимает утверждение и аннулирует несыгранную сетку. При сыгранных зависимых раундах изменение блокируется. Затем требуется повторное утверждение мест и посева. Действия фиксируются в AuditLog.

### Интерфейс

Сохранены обзор, участники, общий список схваток и результаты. Добавлены группы A–D, расписание по турам, таблицы, плей-офф и победители. Публичная карточка `/events/:id` показывает те же спортивные данные без административных кнопок.

В сетке видны счёт, победители и источники будущих пар. На телефоне прокрутка находится внутри контейнера сетки. Проверены ширины 320, 375, 390, 768 и 1024 px. Редакторы используют существующий FormDialog/AdminEditorLayout. В общий редактор результатов также добавлены причины исправления/отмены.

Для нового интеграционного теста задать `TOURNAMENT_TEST_DATABASE_URL` на локальную `kfl_tournament_test` с указанным маркером и выполнить `npm --workspace apps/api run test:tournament`. Без переменной или с другой базой тест откажется запускаться. Пароли в отчёт не включены.

## Решения и ограничения

- Выход мест 1–4 без предварительного раунда утверждён пользователем.
- Доступен первый запрошенный шаблон **4×6**. Произвольное число групп/квалификационных мест в UI не добавлялось. Время, состав и распределение настраиваются.
- FORFEIT трактуется как досрочная техническая победа 4–1, что явно показано в предпросмотре/редакторе. Если регламент различает виды технического поражения, нужна отдельная детализация правила.
- Расписание последовательное с заданным интервалом; отдельная система нескольких ковров не добавлялась.
- Нет бронзового матча, скрытой жеребьёвки и новой формулы глобального рейтинга.
- Не проводились production-нагрузочные испытания и проверка на физических iOS/Android. Playwright использует Edge. Остаются эксплуатационные замечания предыдущего аудита: крупный bundle, унаследованная конфигурация TLS окружения, отсутствие lint-команды.
