# KFL Admin Control Center 3.0

Панель реализована в существующем React-приложении по маршруту `/admin/*`. Публичные страницы, Header, Footer и формулы рейтинга не изменены. Деплой, seed и reset не выполнялись.

## Реализованные разделы

| Раздел | Операции |
|---|---|
| Dashboard | Реальные счётчики, активный сезон, предстоящие турниры, журнал действий, четыре быстрые формы |
| Спортсмены | Поиск, фильтры, серверная пагинация, создание, полный профиль, фото, история, клуб/тренер, архивирование и восстановление |
| Турниры | Создание, редактирование, дата и сезон, переход к связанным схваткам и публичному календарю |
| Схватки | Пара из разных активных спортсменов одной категории, статус, титульный флаг, результат, периоды/штрафы, исправление и отмена с подтверждением |
| Сезоны | Создание, атомарная активация, категории, переход к рейтингу сезона |
| Рейтинги | Выбор сезона/категории, реальные результаты и серверный пересчёт с подтверждением |
| Чемпионы | Действующие чемпионы, защиты, история владения титулом, протоколы титульных схваток |
| Медиа | Черновик, редактирование, обложка, предпросмотр, публикация/снятие с публикации, удаление с подтверждением |
| Заявки | Поиск, статусы, полная анкета, заметки, рассмотрение, одобрение и отклонение |
| Клубы / тренеры | Списки, создание и редактирование, связи с профилями |
| Пользователи | Список без хешей паролей, создание пользователя с ролью; вход в панель только для ADMIN |
| Настройки | Существующие параметры начисления очков и создание весовых категорий |

Общие компоненты обеспечивают загрузку, пустые состояния, повтор запроса после ошибки, валидацию, уведомления, обработку 409, защиту от повторной отправки и обновление TanStack Query. Сохранение профиля недоступно до окончания загрузки фотографии. При 401 сессия сбрасывается; выход удаляет токен и административный кеш.

## Backend

Новый модуль `apps/api/src/adminManagement.ts` подключён к существующему Express-приложению. Сохранены прежние публичные API и маршруты результатов. Добавлены:

- `GET /api/admin/session`, `/lookups`, расширенные `/dashboard`, `/athletes` и `/matches`.
- Полное создание/редактирование спортсменов, `PATCH /api/admin/events/:id`, `PATCH /api/admin/matches/:id`.
- `POST /api/admin/seasons/:id/activate` и `/rankings/recalculate`.
- `GET /api/admin/championships`.
- `GET/POST/PATCH/DELETE /api/admin/media` с идентификатором для изменения/удаления.
- `POST /api/admin/uploads`: PNG/JPEG/WebP до 5 МБ; `/uploads/...` раздаёт сохранённые изображения.
- Списки, создание и редактирование клубов и тренеров; список и создание пользователей.

Новые изменения сущностей и их аудит записываются одной транзакцией. Ошибки уникальности и внешних ключей возвращают 409, отсутствие записи — 404. Серверные детали не раскрываются. Изменить сезон турнира со схватками нельзя. Изменить завершённую пару можно после отмены результата. Редактирование пары и результата сериализовано блокировкой строки Match, затем категории. Пересчёт рейтинга и чемпионства остаётся на backend.

## База и запуск

Использована отдельная локальная PostgreSQL 17.6: `127.0.0.1:55432`, база `kfl_stage2_test` с маркером `KFL_LOCAL_TEST_ONLY`. Чужие серверы PostgreSQL и их данные не затрагивались. Docker отсутствует; используется подготовленный ранее локальный кластер.

Корневой `.env` загружается существующим `apps/api/src/env.ts`. Секреты не менялись и не публикуются. Две существующие миграции применены ранее; контрольные суммы, индекс единственного активного сезона и отсутствие расхождений со schema.prisma проверены. Новые модели и миграции для этого этапа не потребовались.

Обычный запуск из корня: `npm run dev`, панель — `http://localhost:5173/admin`. Если порты 4000/5173 заняты, используйте отдельные порты и согласованные `PORT`, `WEB_ORIGIN`, `VITE_API_URL`. Браузерные тесты самостоятельно запускают API на 4400 и frontend на 5175, затем останавливают их.

Команды проверки:

```powershell
npm run db:local:check
npm run db:local:verify
npm run typecheck
npm test
npm run test:integration
npm run test:browser
npm run build
```

Для ограниченного Windows-окружения этой сессии Node запускался с временным `NODE_OPTIONS=--preserve-symlinks --preserve-symlinks-main`. В обычном терминале это может не требоваться. Браузерные тесты используют установленный Microsoft Edge. Локальная тестовая учётная запись подготовлена скриптом `test:browser:prepare`; её реквизиты находятся только в игнорируемом `.local/browser-admin.json`.

## Границы реализации

- У Event нет отдельного поля статуса. Панель показывает календарное состояние по дате; вымышленные статусы не добавлены.
- Чемпионы определяются результатами. Ручное назначение отсутствует. Исторические титулы без связанного матча по-прежнему требуют сверки и дают 409 при неоднозначном пересчёте.
- Смена ролей существующих пользователей, восстановление паролей и удаление пользователей не добавлены. Удаление спортсмена заменено архивированием с сохранением истории.
- JWT остаётся stateless: выход очищает браузерную сессию, но не отзывает уже выданный токен на сервере. Это существующая модель авторизации; серверный список отозванных сессий не добавлялся.
- Изображения хранятся локально в `.local/uploads`. Для будущего хостинга нужно постоянное хранилище и резервное копирование; автоматическая очистка неиспользуемых загрузок не реализована.
- Проверки проводились в отдельной тестовой базе. Тестовые записи остаются в ней для воспроизведения; это не production-данные и не фиктивная статистика в коде интерфейса.
- Production build предупреждает о размере общего Ant Design chunk больше 500 kB. Сборку это не блокирует; нагрузочные испытания и проверка production-инфраструктуры в этот этап не входят.

Интеграционный прогон проверяет JWT/401/403, единственный активный сезон, конкурентное одобрение, весовые категории, титульный результат/защиту, повторное сохранение, исправление и отмену, откат при поздней ошибке, новые CRUD, публикации, загрузку и раздачу изображения, отсутствие хешей в пользовательском API и одновременное редактирование пары с результатом.

Браузерный прогон проверяет все 13 маршрутов; каждый раздел на ширинах 375, 390, 768, 1024 и 1440 px; Drawer и размеры формы; создание/редактирование/архивирование спортсмена с фото; создание пары, повтор результата, смену победителя и отмену; медиа; восстановление после 503 и сохранение формы при 409; одобрение заявки; создание/редактирование турнира; защиту от двойной отправки; вход/выход и перезагрузку после выхода. Выпадающие списки проверяются с клавиатуры и прокруткой виртуализированного списка.

Вручную просмотрены снимки desktop Dashboard, мобильного Dashboard и Match Control Center. Все числа на снимках получены из отдельной тестовой базы. Backend и панель готовы к дальнейшему развитию административных функций в пределах описанной модели.
