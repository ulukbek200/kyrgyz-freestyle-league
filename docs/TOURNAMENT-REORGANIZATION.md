# KFL: независимые спортсмены и турниры

## Реализовано

- Профиль спортсмена создаётся без сезона, турнира и регистрации на соревнование. Клуб и тренер вводятся текстом; существующие записи переиспользуются.
- Возраст профиля определяется по календарному году сервера; допуск к турниру — по году даты турнира. Старые участия сохраняют собственные дивизион и категорию.
- Сезоны убраны из форм, фильтров и навигации. Старые адреса страниц перенаправляются в турниры. Архивные таблицы, внешние ключи и чтение `/api/seasons` сохранены для совместимости.
- Схватки создаются и редактируются внутри турнира. Глобального раздела управления схватками нет; существующие API результатов сохранены.
- Турнир имеет город, место, дату, дивизион, набор категорий, описание и статус. После создания открывается его страница с вкладками «Обзор», «Участники», «Схватки», «Результаты».
- Участник выбирается из реестра с поиском по имени/клубу и фильтром веса. Из формы можно перейти к созданию профиля и вернуться в участников турнира. Регистрация после возвращения подтверждается отдельно.
- Уникальность `(eventId, athleteId)` защищена БД. Допуск, регистрация, пары и аудит проверяются в транзакциях. Участника со схватками удалить нельзя; удаление обычной регистрации сохраняет профиль.
- Результаты, рейтинги и история титула сохраняются атомарно. Повторный результат не добавляет защиту. Исправление и отмена пересчитывают производные данные.
- Счёт побед/поражений в реестре и профиле учитывает завершённые схватки во всех категориях, а не первую запись рейтинга. В истории встреч исправлено отображение имени самого владельца профиля.

## Миграция и сохранность

Миграция применена к помеченной локальной базе `127.0.0.1:55432/kfl_stage2_test`, схема `public`. Production не использовалась. Seed/reset не выполнялись.

Резервная копия перед миграцией: `.local/backups/divisions-2026-10-13T17-16-13.882Z.json`.
Скрипт сравнения подтвердил сохранность исходных значений: 2 спортсмена, 1 сезон, 1 турнир, 12 категорий, 23 заявки. В этой копии ещё не было схваток, результатов, рейтингов и титулов.

Четыре миграции применены; контрольные суммы совпадают. `prisma migrate diff` не обнаружил расхождений с моделью. Слишком длинное имя существующего индекса PostgreSQL закреплено через `map`, без перестроения индекса.

Для другой базы: сначала резервная копия и аудит истории, затем проверка назначения подключения, `npm run db:deploy` и `npm run db:generate`. Не использовать reset или seed на существующих данных.

## Проверки

- `npm test`: 38 тестов без записи в БД.
- `npm run test:integration`: 8 последовательных сценариев HTTP API (9 успешных тестов с родительским тестом). Для каждого прогона создаётся отдельная случайная схема `kfl_it_<uuid>`, в неё применяются миграции; после прогона удаляется только эта схема. Данные сайта в `public` не используются как фикстуры.
- Покрыты создание независимого профиля, заявка/повторное одобрение, турнир, участники, дубликаты, удаление регистрации, пары, рейтинг, титул, повтор/исправление/отмена результата, откат при ошибке аудита, переход дивизиона по году турнира, закрытие регистрации и приватность публичных ответов.
- `npm run typecheck`; дополнительно TypeScript frontend-тестов и проверки `--noUnusedLocals --noUnusedParameters` обоих пакетов.
- `npm run build`: backend и frontend. Vite предупреждает о крупном пакете Ant Design; это предупреждение размера, не ошибка сборки.
- `npm run db:local:verify`: контрольные суммы и отсутствие дрейфа схемы.
- Playwright `--list`: 12 сценариев успешно обнаружены. Сам браузерный прогон не выполнялся; визуальная проверка, загрузка фотографии через UI и размеры 375/390/768/1024/1440 остаются для ручной проверки пользователя. HTTP-доступность Vite не считается визуальной проверкой.

## Ограничения исторических данных

- Если миграция применяется к базе со старыми схватками, восстановленные участия помечаются `NEEDS_REVIEW`. Это сохраняет историю без предположений о допуске. Для новых пар с такими участниками нужна отдельная сверка протоколов. Существующие результаты доступны; автоматическое исправление неоднозначной истории не выполняется.
- Архивные рейтинги сохраняются с прежним seasonId. Для базы с прежними результатами общий рейтинг каждой категории можно пересчитать существующей кнопкой «Пересчитать» в админке; новые результаты обновляют его автоматически. В текущей локальной базе архивных результатов нет.
- Вкладка «Результаты» показывает места по действующей формуле рейтинга KFL внутри категории. Она не вводит новую систему олимпийской сетки/медалей.
- Команда браузерных тестов использует локальное тестовое окружение из Playwright-конфигурации и создаёт фикстуры. Не запускать её на данных для ручной проверки без отдельного окружения. В этой работе она не запускалась.

## Ручная проверка

Открыть `http://localhost:5173/admin/athletes`, создать профиль, затем создать турнир в «Турнирах». Добавить двух участников через вкладку «Участники», создать пару во вкладке «Схватки», сохранить результат и проверить вкладку «Результаты». API для этого frontend работает на порту 4401.
