# KFL — исправления B01, B02, B03, B11

Дата: 14 октября 2026. Основание: `TECHNICAL-AUDIT-2026-10-14.md`.

## Выполнено

### B01 — актуальные права и отзыв сессий

Каждый защищённый запрос читает User из PostgreSQL. Проверка доступа использует актуальную роль, а не роль из JWT. Отсутствующий или заблокированный пользователь получает 401. Ошибка БД передаётся централизованному обработчику Express 4; доступ при ошибке не предоставляется.

Добавлены `User.isBlocked` (false) и `User.sessionVersion` (0). Токен связан с пользователем, хешем пароля и версией сессии через HMAC; сам пароль и его bcrypt-хеш в JWT не помещаются. Изменение пароля, включая прямое изменение passwordHash в БД, отзывает старый токен.

Добавлен защищённый `PATCH /api/admin/users/:id` для `{role?, isBlocked?, password?}`. Изменения увеличивают sessionVersion атомарно с записью пользователя и audit log. Разблокировка не восстанавливает старые сессии. В ответе нет passwordHash/sessionVersion. Существующие API сохранены; интерфейс управления пользователями не перерабатывался.

JWT, выпущенные до этого обновления, не содержат подтверждения версии сессии и отклоняются. **Потребуется повторный вход. Пароли пользователей не изменялись.**

### B02 — валидация и fallback баннера

Создание/изменение турнира принимает только корректный абсолютный http(s) URL без credentials либо разрешённый `/uploads/<id>.<png|jpg|webp>`. `http://`, `https://`, javascript URL, protocol-relative URL и некорректные адреса отклоняются с 400.

Frontend разрешает URL внутри try/catch. Неверная историческая ссылка, отсутствие картинки и ошибка загрузки используют существующий `/media/kfl-hero-poster.webp`. Если недоступен и fallback, картинка скрывается, но текст и ссылка турнира остаются. Исторические URL в рабочей БД не переписывались и не удалялись.

Проверено не только с перехватом HTTP в Playwright: в отдельную тестовую БД записан исторический `bannerUrl: "http://"`; реальный `/api/events/upcoming` его вернул, главная загрузилась без React errors и показала fallback. Скриншот проверен визуально: `.local/priority-20261014/historical-banner.png`.

### B11 — ограничение входа

- На IP: 60 запросов входа за 15 минут, независимо от email.
- На нормализованный email: 10 неуспешных попыток за 15 минут, независимо от IP; успешные запросы не расходуют этот счётчик.
- Ответ при превышении — 429 с Retry-After; сообщение одинаково для существующего и отсутствующего аккаунта.
- Неверный пароль, заблокированный и отсутствующий пользователь возвращают одинаковые 401/JSON. Для отсутствующего пользователя также выполняется bcrypt comparison с dummy hash.
- По умолчанию `trust proxy=false`. `TRUSTED_PROXIES` позволяет указать доверенные IP/CIDR прокси. Значения true, числовой hop count и `/0` отвергаются. Прокси должен перезаписывать X-Forwarded-For; нельзя включать доверие всем клиентам.

Использована уже установленная express-rate-limit, без новых зависимостей. Счётчики находятся в памяти одного процесса, сбрасываются при его перезапуске. **Для нескольких API-реплик нужен общий rate-limit store либо общий лимитер на ingress.** Такая распределённая инфраструктура в этом этапе не добавлялась и не проверялась.

### B03 — отменённые турниры

Перед записью результата транзакция блокирует Match, Event и WeightClass и проверяет статус турнира. Для CANCELLED новый результат незавершённого матча получает 409. Отмена турнира использует ту же блокировку Event, поэтому проверка статуса согласована с записью.

Уже завершённый матч можно повторно сохранить, исправить или отменить; рейтинги и чемпионство пересчитываются существующим механизмом. Само действие отмены турнира не меняет старые результаты. После удаления результата повторное создание в CANCELLED вновь запрещено. Порядок блокировок при изменении пары согласован с сохранением результата, чтобы не вводить обратный порядок event/weight.

## Оставшиеся ограничения

- B12 — восемь прежних ошибок локаторов тестов — вне разрешённого объёма этого этапа.
- Остальные замечания аудита, кроме B01/B02/B03/B11, не исправлялись. В частности, предупреждение о chunk Ant Design >500 кБ и dependency advisory сохраняются.
- Proxy-конфигурация и счётчики проверены локально. Production reverse proxy, несколько реплик и длительная нагрузка не проверялись.
- Блокировка/смена пароля доступны через защищённый API; отдельный новый интерфейс этих действий не добавлялся.
- Полный стресс-тест конкурентных отмен/результатов не выполнялся; корректность штатного повторения, исправления, отмены и транзакционного rollback проверена с PostgreSQL.

Четыре приоритетных дефекта исправлены и покрыты регрессиями. Это не означает закрытие всех замечаний полного аудита или готовность к production.
