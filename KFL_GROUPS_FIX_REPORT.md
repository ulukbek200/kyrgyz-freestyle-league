# KFL — уникальное распределение спортсменов по группам

15 октября 2026 года.

## Причина и исправление

`GroupSetup` в `apps/web/src/GroupCompetition.tsx` передавал одинаковый полный список участников во все 24 поля. Сервер уже отклонял повторения через `checkedPreview` → `previewGroups`, но интерфейс позволял их выбрать.

- Выбранный спортсмен исключается из остальных полей всех четырёх групп; своё поле продолжает показывать выбранное имя.
- Добавлена очистка места. Для переноса нужно очистить прежнее место и выбрать спортсмена в новом. Обработчик дополнительно освобождает прежний слот при повторном назначении одного ID.
- Варианты ограничены активными участниками выбранной весовой категории текущего турнира с активным профилем.
- Заголовки показывают заполнение: «Группа A — 4/6».
- Предпросмотр и подтверждение доступны только для 24 уникальных допустимых ID в четырёх группах по шесть мест. Изменение выбора сбрасывает предпросмотр.
- Автораспределение допускает только 24 разных спортсмена.
- Серверная проверка выполняется и для предпросмотра, и для сохранения в транзакции. Улучшено сообщение: «Один спортсмен выбран несколько раз. В категории турнира спортсмен может занимать только одно место в одной группе. Уберите повторный выбор».

## Изменённые файлы

- `apps/web/src/GroupCompetition.tsx` — поля, фильтрация, перенос, счётчики и проверка заполнения.
- `apps/api/src/groupSchedule.ts` — понятная серверная ошибка повторного назначения.
- `apps/api/tests/tournamentSystem.integration.ts` — прямые запросы с дублями внутри/между группами, неполным составом и посторонним участником; проверка отсутствия частичных записей.
- `apps/web/tests/tournament-system.spec.ts` — исключение выбранного спортсмена из других полей, очистка и перенос, другая категория, счётчики и автозаполнение.
- `KFL_GROUPS_DATA_AUDIT.json` — результат проверки сохранённых распределений.
- `.local/audit-group-duplicates.mjs` — повторяемая проверка в транзакции READ ONLY с проверкой назначения локальной БД.

## Аудит существующих данных

Рабочая локальная база: `kfl_stage2_test`. Найдено **0 сохранённых распределений TournamentFormat**, обнаружено **0 дубликатов**. Это означает, что сохранённых групп для сверки пока нет, а не что в каждой уже существующей группе проверено 24 спортсмена.

Автоматические исправления данных не выполнялись. При выявлении исторических дублей безопасный порядок: резервная копия, сверка состава с протоколом и уже созданными схватками, отдельный план корректировки с сохранением результатов и аудитом; не удалять спортсменов или результаты автоматически.
